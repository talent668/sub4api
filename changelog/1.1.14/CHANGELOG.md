# v1.1.14

## 调试与请求诊断

- 左侧「操作日志」页面新增「操作日志 / 调试日志」切换；支持 `/admin/audit-logs?tab=debug` 直达、刷新保留选择及浏览器前进/后退。系统设置中保留「调试 / 日志」入口。
- 复用运维日志系统，新增独立的「将请求诊断写入数据库」开关，默认关闭。开启后可在页面近实时查看已结束的 Messages HTTP→WS 尝试；无需全局启用 Debug，也不会自动开启所有访问日志入库。
- 日志支持约 2 秒自动刷新、筛选及分页；查看历史页、阶段详情或隐藏页面时暂停刷新，避免列表跳动与旧响应覆盖。
- 新增 WS 阶段耗时：请求准备、完整连接获取、写入前处理、请求写入、上游首事件/首语义等待，以及连接复用状态。区分首语义、首文本和尝试总时长，缺失阶段不伪装为零。
- 详情支持可折叠、语法高亮的安全 JSON 及复制：区分客户端原始参数、最终上游参数、安全请求头、连接握手响应元数据和上游响应声明；不将出站服务档位冒充上游回声。
- 用量展示仅采用明确报告的输入、输出、缓存读取、缓存创建、推理和总 Token；保留显式零，未报告的字段不补零，也不重复累加推理/缓存细分。
- 诊断采用源端投影、入库重校验、前端重投影三层白名单；不采集提示词、输入/输出正文、推理内容、工具参数、Authorization、Cookie、API Key、票据及会话标识。握手信息明确标注为连接级，复用时不冒充逐轮响应头。

## 诊断日志自动保留

- 仅请求诊断日志默认保留 7 天，可独立设置 1–3650 天，以及 0–102400 MiB 的记录容量上限；0 表示关闭容量限制。
- 后台按天数和容量从最旧记录开始分批清理；独立于诊断采集开关与通用运维清理开关，保存收紧策略前提示不可恢复的删除风险。
- 使用跨实例锁、单轮删除/扫描上限及查询超时，不在业务请求或日志写入热路径执行清理；设置持久化失败不启用新的删除策略。
- 容量为逻辑记录数据量估算，不是 PostgreSQL 物理磁盘硬配额；超出单轮安全扫描能力时暂停容量裁剪并提示未完成，不猜测删除范围。删除不保证数据库文件立即缩小。
- 操作审计、计费使用记录、其他系统日志、清理审计和日志文件保持原策略；通用自动清理排除诊断记录，避免覆盖诊断专属保留期。

## 网关准备路径优化

- Messages→WS 复用与最终策略请求体完全一致的已准备 Codex 请求 map，减少适用路径的重复 JSON 解析和分配；策略改写时仍使用最终请求体完整解码，HTTP 回退字节保持独立。
- 保持数字精度，覆盖大整数、小数和指数形式的工具 schema；不改变模型映射、Fast/推理强度、WS 连接隔离、输出 flush、首字定义及取消后的用量排水。
- 本次没有实施直接事件适配、重复帧校验消除、并发槽位定向唤醒或 flush 合并；不能据此承诺消除 WS 首字中的秒级上游等待。

## 升级说明

- 本版从 `release/1.1.14` 发布，不合并到 `main`。
- 无新增数据库结构迁移；新增策略使用既有运行时设置及系统日志存储。升级前仍建议备份 PostgreSQL。
- 诊断默认关闭，只对开启后产生的新请求采集；旧记录不追补参数、Token 明细或分段耗时。
- 新的诊断保留策略加载后会清理超过默认 7 天的诊断历史；需要更长保留期时，请在启用/升级前评估并备份数据。原操作审计与计费明细不受影响。
